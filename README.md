# Carl AI

Carl is an independent agent application built on the KofTwentyTwo Agent Foundation. Its first-release financial mission is to reduce debt and make sustainable cash-flow plans, then improve rental/tax structure and plan investment against agreed milestones. Carl owns its domain records, services, reasoning and QQQ administration. External financial/vendor actions remain human-led; the designated shared Synology calendar/reminder workspace has separately authorized maintenance scope.

## Build and local verification

Use Java 21, Maven 3.9+ and Docker for disposable PostgreSQL tests. Run `mvn spotless:apply verify`; the distribution is `target/agent`. Open this directory as a Maven project in IntelliJ, select Java 21 for the project and Maven runner, and run the same `verify` lifecycle. `AgentApplication.main` and tests use the same component factory.

The current parent is `com.kof22:kof22-agent-parent:0.5.0-SNAPSHOT`, now independently published and qualified from foundation main d0a11bf/run36974782652. The development CI pin records all nine identities in `config/ci/foundation.json`; matching consumer qualification is separate. Carl’s current frozen package was built with separately qualified local development artifacts; use `-Dmaven.repo.local` for that exact cache. Fresh Carl remote resolution still requires authorized private package credentials. The remote release baseline in `config/release/foundation.json` deliberately remains0.4.1: RC/stable promotion will refuse this development parent until its matching foundation release is published and independently qualified. A clean public-consumer checkout still needs private Maven package access for published artifacts. The final consumer build is verified separately from upstream publication. The consumer repository token alone is not assumed to grant cross-repository package access. Supply secrets privately through the environment and use `--settings config/maven/settings.xml.example`; do not store a token in this repository.

The following browser fixtures are controlled regression tooling only. Never offer fixture sign-in, fictional records or scripted providers as the working Carl UI. Run packaged browser checks with `npm ci --prefix scripts/e2e`, `npx --prefix scripts/e2e playwright install chromium`, then `bash scripts/verify-browser.sh` after the Maven build. The fixture uses synthetic PostgreSQL records and local TLS/OIDC; ordinary checks use a disconnected model. Set `CARL_QUALIFIED_DISTRIBUTION` to the reviewed distribution and run `scripts/verify-dashboard-browser.sh` and `scripts/verify-talk-browser.sh` for the native process UI checks; run `scripts/verify-docked-chat-browser.sh` for the dock; `scripts/verify-qbits-browser.sh` checks actual OpenSearch and Artemis integration. Live synthetic preview inference is separately opt-in and requires the already-authorized credential through the foundation runtime variable `KOF22_AGENT_ANTHROPIC_API_KEY` (the unprefixed legacy name is not read by the harness); never paste it into source or configuration. Optional `MAVEN_SETTINGS` and `MAVEN_REPO` select an isolated qualified development cache.

Run the [representative model evaluation](docs/EVALUATION.md) against the frozen reviewed package. Controlled tooling is qualified; real model cases require an explicitly selected model and privately supplied authorized credential.

See [operator instructions](docs/OPERATOR-RUNBOOK.md), [family API integration](docs/CLIENT-INTEGRATION.md), and [acceptance evidence](docs/ACCEPTANCE.md). Do not connect personal sources or expose this development application publicly until the outstanding acceptance and deployment work is qualified.
