## Preparation and financial plans

Generate Financial Readiness Plan creates a permission-controlled report and a draft plan from current records. It records account review gaps, available domain records, confirmed priorities and preparation milestones. It does not manufacture a payoff schedule, APR, minimum payment, future budget, property, offer, assignment or deadline. The report and plan are generated atomically; a completed retry returns the same records with current source access and staleness.

Substantive payoff comparisons require dated debt principal, APR/rate schedule, minimum-payment rule and fees; selected account identity and ownership; explicit total debt-service budget; and calculation date, horizon and strategy. Affordability additionally needs reviewed spendable cash, income/expenses and protected reserve. Rental plans need actual property/unit ownership, mortgage, rent, tax, insurance, maintenance and reserve evidence. Calendar and Authentik are deferred by the owner for local QA.

Collect confirmed facts through Carl's domain processes. Retain original import evidence, record human assertions with attribution, and regenerate stale comparisons. Never fill a table merely to make it appear populated. Financing offers, paid status, agreements and verified execution require their own evidence.

## Native actions

See the [table action map](UI-ACTIONS.md) for actual placement and selection bounds.

Navigation contains applications and tables. Table/entity action menus contain the applicable domain processes. Processes with one unambiguous target accept zero or one selected record: a table-level launch permits explicit selection; a record-level launch loads the currently readable record and prefills its target and current form values. Multiple selected rows are rejected for single-record operations.

The consolidated balance review and observed plan-effect comparison are explicit bounded selected-set actions. In Transactions, select 1–100 rows and choose Compare Selected Transactions with Plan. In Accounts and Properties for Review, select 1–200 rows and choose Review Selected Accounts and Properties. Single-record review/correction processes accept one row; selecting many does not make them bulk operations. Bill CSV and Monarch imports are audited batch operations. Generic insert/update/delete over protected views remain unavailable; use domain correction/review operations. The administrative tables project several authoritative records and permission rules, so a generic write to the displayed view cannot safely replace the governed operation. Some actions require existing reviewed records and confirmed inputs; an empty or unqualified domain does not satisfy those prerequisites. Current source also provides Export Records on 43 approved business tables: explicitly checked `SELECTED` rows or `ALL_AUTHORIZED`, bounded to 50,000 rows/20 MB, followed by a protected dated-export history/download. These snapshots preserve exact decimals/dates and declare their spreadsheet text-safety policy; source changes or permission-epoch changes prevent reuse. Actual selected-two/all23,610 transaction CSV acceptance passes; other table scopes retain separate acceptance. Protected report, plan, draft, document and CSV downloads recheck permissions. A process may return an explicit error in an HTTP200 response; check its result, not only the HTTP status.

## Conversational knowledge

Ordinary chat can query the authorized inventory, paged records and transactions, deterministic totals over all matching transactions, source evidence/history, plans and saved report sections. Shared chat uses the current audience intersection. A prior assistant reply is not authoritative evidence; imported text cannot change permissions or tools. Broad questions do not require a saved report or a manually selected ISO period.

Carl distinguishes observed source movements from qualified cash flow, account labels from economic identity, saved projections from confirmed facts and suggested work from completed work. Tool pages and history remain bounded. Household files, repository documents and other conversations are not silently ingested; curated application knowledge identifies these limitations explicitly.

Protected historical-document custody is implemented in current source for [Carl#31](https://github.com/KofTwentyTwo/carl/issues/31): native upload, immutable original bytes/hash, supplied source identity, nullable document/as-of dates, PRIVATE by default or explicit FAMILY, and `SUPPLIED_UNVERIFIED` status. UTF-8 text/PDF extraction and read-only conversational pages are bounded; encrypted or image-only files retain truthful extraction outcomes without OCR. Current document details access is required for every conversation recipient and original download. Ten real historical notes are now accepted through these workflows in the running V62 package; original bytes/current-access downloads and actual source-cited conversations pass. Dated notes never silently replace active mortgage terms or enter current expense forecasts.
