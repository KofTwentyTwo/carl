# Carl navigation and System

Carl's native navigation lists applications and tables. Ordinary processes retain their IDs, permissions and direct URLs, and appear through QQQ's table associations: for example, reviewed transaction actions belong to Transactions, bill entry/import belongs to Bills, Monarch uploads and reconciliation belong to Import History, plan creation belongs to Plans, and task/check-in actions belong to Plan Steps. Existing record-selection processes retain their selected-record limits; form-based actions require no selected rows. New processes must declare a registered contextual table instead of becoming sidebar links.

System contains the registered Operations and optional ESB applications, preserving their native permissions and tables. The application factory must include `new ZCarlSystemNavigation()`; its app-output producer runs after optional QBits metadata and updates the hierarchy in place. Database is an ADMIN-only native widget backed by the same Carl service. It additionally requires an active household manager with current SETTINGS access, and rechecks scope before returning. It shows a fixed connection label, current database/schema and at most 200 tables with PostgreSQL table/index/total bytes. It performs bounded read-only queries, includes no row counts, JDBC URL, host, user or password, and accepts no user SQL or connection target. This is storage inspection, not backup/restore or production readiness evidence.
