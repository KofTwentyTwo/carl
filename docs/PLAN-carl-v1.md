# Carl version 1 design and execution

One Java application inherits the foundation lifecycle and supported packaging; PostgreSQL is its authoritative state and QQQ its administrative interface. Explicit Java domain services implement calculations, authorization and transactions. Caller-aware read tools expose those services to reasoning. Human-initiated import/correction/report/draft processes call the same services, with idempotency keys and provenance. No external write tools or client methods exist. Production and tests use one component factory, replacing only external boundaries.

Persist typed household/member/grant records, sources/import outcomes, bills and corrections, vendor work, read-only calendar projections, drafts/reports and preferences. Deny unmapped/inactive principals, restrict each query before model context construction, and use an explicit audience intersection for shared reports. Recheck grants on retrieval/export. Source evidence is immutable; local corrections record attribution. Exact decimal totals remain separate by currency. Date-only bills use an explicit household zone; event instants preserve source zones/all-day dates. CalDAV is a bounded read-only adapter with same-origin targets and controlled fixture tests.
